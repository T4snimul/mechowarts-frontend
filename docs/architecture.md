# Architecture

## Overview

The application follows a feature-based architecture.

The App Router is responsible only for routing.

Business logic belongs inside features.

Reusable UI belongs inside components.

Utilities belong inside lib.

---

# Folder Structure

app/
components/
features/
hooks/
lib/
services/
stores/
types/
config/

---

## app/

Contains Next.js routing and framework entry files.

Examples:

- page.tsx
- layout.tsx
- loading.tsx
- error.tsx
- not-found.tsx
- route.ts
- favicon.ico
- globals.css
- robots.ts
- sitemap.ts
- manifest.ts

Business logic does not belong here.

Pages should compose feature components rather than implement business logic directly.

---

## components/

Contains reusable UI shared across the application.

Components in this folder must be generic and reusable.
They must not contain feature-specific business logic.

Folder structure:

components/

    ui/            # shadcn/ui components

    shared/        # reusable application components

    layout/        # layouts and navigation

    providers/     # React providers

    icons/         # custom SVG and icon components

---

### ui/

Contains components generated by shadcn/ui.

Examples:

- Button
- Card
- Input
- Dialog
- Table

These components are the foundation of the design system.

Do not place application-specific logic here.

---

### shared/

Reusable components used by multiple features.

Examples:

- Logo
- SearchBar
- UserAvatar
- EmptyState
- LoadingSpinner
- PageHeader

Shared components may compose shadcn components.

---

### layout/

Application layout components.

Examples:

- Navbar
- Sidebar
- Footer
- DashboardLayout
- AuthLayout

---

### providers/

Application-wide React providers.

Examples:

- ThemeProvider
- QueryProvider
- TooltipProvider

Providers are registered from the root layout.

---

### icons/

Custom SVG icons and icon wrappers.

Do not duplicate icons that already exist in lucide-react.

---

### Rules

- Components should have a single responsibility.
- Reuse existing components before creating new ones.
- Keep components presentation-focused.
- Business logic belongs in features or services.
- Components may use hooks but must not perform API requests directly.

---

### Not Allowed

The following do NOT belong here:

- LoginForm
- RegisterForm
- ProfileCard
- ProjectCard
- ChatWindow

Feature-specific components belong inside their respective feature folders.

---

## features/

Contains complete application features.

Example:

features/auth

features/profile

features/chat

features/projects

Each feature owns its own:

- components
- hooks
- services
- schemas
- types

---

## lib/

Application utilities.

Examples:

api client

auth

constants

helpers

validators

---

## services/

Communication with backend.

Only services make HTTP requests.

Components never call fetch() directly.

---

## hooks/

Reusable hooks shared across multiple features.

---

## stores/

Global Zustand stores.

Do not store server state here.

---

## types/

Global TypeScript types.

---

## config/

Application configuration.

Example:

navigation

roles

permissions

environment

---
